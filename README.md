# rag_parse

`rag_parse` 正在转向一个开源的**个人行为先兆预判 / 基线漂移解释 Agent**。系统拟将经过授权的日常观测整理为个人时间线，识别相对于个人情境化基线的变化，结合历史与上下文生成可追溯的线索，交由人复核。

这里的“先兆预判”指**较早发现值得复核的变化**。项目当前不提供疾病诊断、病因判断、治疗建议或经过临床验证的未来风险预测。原型的分析结果不能用于紧急处置。

## 目标链路

```text
授权观测（首版 CSV/JSON 与模拟记录；后续 HealthKit/语音）
  → 时间对齐、质量与缺失检查
  → 多时间窗口个人基线
  → 统计漂移和变点检测
  → 历史相似片段、上下文与证据
  → 受控 Agent 生成待复核线索
  → 人工复核、结果回写与离线评测
```

数值检测由可测试的统计逻辑负责；Agent 负责查询经过授权的证据、整理不确定性并生成复核案例。计划用 Python 构建核心能力，以 LangGraph 编排有限步骤，以 LangChain 接入模型、消息和工具。PostgreSQL 保存业务真相；Qdrant 仅在需要时辅助检索历史相似事件，不能替代时间序列基线计算。

## 阶段计划

| 阶段 | 重点 |
| --- | --- |
| 0 | 预期用途、授权与撤回、数据分级、核心事件契约 |
| 1 | 使用合成或许可适用数据建立离线观测、基线和漂移闭环 |
| 2 | 历史证据、上下文、人工复核案例与结果回写 |
| 3 | 模型调用治理与受控 Agent 工作流 |
| 4 | HealthKit、照护者输入和可选语音适配 |
| 5 | 离线评测、误报负担、可选多 Agent 扩展 |
| 6 | 文档解析与知识引用：最后接入照护记录、报告和指南 |

文档解析保留为最后一个独立模块。它为解释提供带原文定位的知识证据，不参与个人数值基线或漂移检测。

## 当前进度

新方向目前处于规划阶段。仓库里的 FastAPI、BFF/Web、Docker Compose、模型策略等来自此前的内网文档 RAG 原型；它们尚未按新用途验收。当前没有个人观测、基线、漂移检测、HealthKit 或复核闭环实现。开发与评测首先使用合成或许可适用的去标识数据，真实个人记录需要先完成授权、撤回、存储与删除机制。

旧项目的[安全与模型外发策略](docs/security-and-model-policy.md)保留为历史安全基线。其默认拒绝外发、最小权限和审计原则可复用；原文中的知识库、核物理资料和 BFF 阶段安排不是当前开发顺序。

详细现行规划及新线程交接稿保存在本机 `temp/个人行为先兆预判Agent/`。`temp/` 当前不纳入 Git，因此仓库公开版以本 README 为项目入口；落地细节以当前仓库代码和实际测试为准。
